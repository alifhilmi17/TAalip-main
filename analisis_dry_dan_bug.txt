BAGIAN 1: ANALISIS PELANGGARAN DRY (DON'T REPEAT YOURSELF)
------------------------------------------------------------------------
Prinsip DRY menyatakan bahwa setiap bagian dari pengetahuan sistem harus
memiliki representasi tunggal, tidak ambigu, dan berwenang. Di dalam
proyek ini, ditemukan 2 pelanggaran DRY yang cukup signifikan:

1. Reduplikasi Struktur HTML Sidebar (aside & main-nav)
   - Lokasi Masalah:
     Hampir di setiap file halaman dashboard (seperti dashboardTAalip.html,
     dataAyamTAalip.html, inputproduksi.html, kesehatanayam.html,
     keuangan.html, stokpakan.html, restockreminder.html, prediksihasil.html,
     dokumen.html, dan editProfileTAalip.html).
   - Penjelasan Pelanggaran:
     Seluruh elemen navigasi samping (<aside> beserta <nav class="main-nav">)
     disalin secara manual di setiap halaman. Untuk memperbarui menu ini,
     Anda terpaksa menggunakan skrip Python tambahan (update_sidebar.py)
     yang bertugas mencari dan mengganti kode HTML tersebut di semua file.
   - Mengapa Ini Buruk:
     Jika Anda menambahkan halaman baru, Anda harus memodifikasi skrip Python
     dan menjalankannya kembali. Ini rawan error jika format tag HTML di
     satu file sedikit bergeser karena skrip regex tidak akan mendeteksinya.
   - Solusi Bersih (Recommended):
     Gunakan dynamic loading untuk sidebar menggunakan Vanilla Javascript
     (Fetch API). Pindahkan HTML navigasi tersebut ke satu file terpisah, 
     misalnya `components/sidebar.html`, lalu gunakan script sederhana 
     di `js/ui-utils.js` untuk melakukan fetch dan memasukkannya ke elemen 
     kontainer aside secara dinamis saat halaman dimuat.

2. Duplikasi dan Konflik Fungsi toggleSidebarMenu
   - Lokasi Masalah:
     Ada 3 versi berbeda dari fungsi ini yang didefinisikan secara global:
     a. js/ui-utils.js (Garis 11):
        window.toggleSidebarMenu = function(submenuId) { ... }
     b. restockreminder.html (Garis 244):
        window.toggleSidebarMenu = function (id) { ... } (Inline Script)
     c. admin.frontend/admin-core/admin.js (Garis 1013):
        window.toggleSidebarMenu = function(id) { ... }
   - Penjelasan Pelanggaran:
     Logika untuk membuka/menutup accordion submenu di sidebar dibuat 
     berulang-ulang dengan algoritma yang sedikit berbeda (ada yang memakai
     toggling class 'show' & 'active-parent', ada yang memakai class 'open',
     serta ada yang menggunakan manipulasi aria-attributes secara manual).
   - Mengapa Ini Buruk (Menimbulkan Bug Visual):
     Pada `restockreminder.html`, script `js/ui-utils.js` di-load paling 
     bawah (setelah inline script). Hal ini membuat fungsi inline di 
     `restockreminder.html` langsung tertimpa (overridden) oleh fungsi global 
     dari `ui-utils.js`. Akibatnya, fungsionalitas sidebar pada halaman 
     tersebut dapat berjalan tidak konsisten karena terjadi bentrokan 
     styling class antara '.open' dan '.show'.
   - Solusi Bersih (Recommended):
     Hapus inline script di `restockreminder.html` dan modifikasi fungsi 
     global di `js/ui-utils.js` agar menjadi satu-satunya standard universal
     yang menangani transisi CSS submenu (baik dengan class `.show` maupun
     `.open` secara konsisten).

BAGIAN 2: AUDIT BUG KECIL & KERENTANAN LOGIKA
------------------------------------------------------------------------
Berdasarkan hasil analisis runtime logic dan verifikasi relasi data, 
ditemukan beberapa bug kecil yang sangat krusial untuk segera diperbaiki:

1. BUG KRUSIAL: Pengalihan Sesi (Redirection) ke File Terhapus adminlogin.html (404 Error)
   - Lokasi Masalah:
     a. firebase.component/auth-state.js (Garis 223 - 243)
     b. admin.frontend/admin-core/admin.js (Garis 315, 319, 322, dan 996)
   - Deskripsi Masalah:
     Sebelumnya, file adminlogin.html, adminlogin.css, dan adminlogin.js 
     telah dihapus secara total dari folder `admin.frontend/` karena alur 
     login admin telah disatukan di halaman login utama (`login.html` di root).
     Namun, logika di `auth-state.js` dan `admin.js` masih mengarahkan
     proses logout atau kegagalan otentikasi admin ke halaman `adminlogin.html`
     yang sudah tidak ada tersebut.
   - Akibat:
     Setiap kali Admin melakukan klik tombol "Logout" dari panel admin, 
     atau ketika sesi admin kedaluwarsa secara otomatis, halaman akan
     diarahkan ke halaman kosong berstatus 404 (File Not Found).
   - Solusi Perbaikan:
     a. Di `firebase.component/auth-state.js` fungsi `redirectBasedOnRole`, 
        ganti semua rujukan `adminlogin.html` menjadi `login.html` dengan 
        relative path yang sesuai:
        ```javascript
        if (isAdmin) {
            if (isAdminCore) {
                window.location.href = '../../login.html'; // Naik dua tingkat ke root
            } else if (isAdminRoot) {
                window.location.href = '../login.html'; // Naik satu tingkat ke root
            } else {
                window.location.href = 'login.html'; // Tetap di root
            }
        }
        ```
     b. Di `admin.frontend/admin-core/admin.js` (Garis 315, 319, 322, dan 996), 
        ganti seluruh rujukan `../adminlogin.html` menjadi `../../login.html`.

2. Ketidaksesuaian Visual Notifikasi (alert() Bawaan vs SweetAlert2)
   - Lokasi Masalah:
     a. firebase.component/signup-interactive.js (Garis 72 & 97)
     b. firebase.component/login-interactive.js (Garis 288)
   - Deskripsi Masalah:
     LIBAS telah mengadopsi SweetAlert2 (`Swal.fire`) secara premium hampir
     di seluruh antarmuka dasbor untuk menampilkan pesan sukses dan eror. 
     Namun, pada modul otentikasi (`signup-interactive.js` dan
     `login-interactive.js`), pesan kesalahan password lemah, email sudah
     terdaftar, atau gagal masuk masih dikomunikasikan lewat jendela popup
     `alert()` bawaan browser yang terkesan standar dan kaku.
   - Solusi Perbaikan:
     Karena pustaka SweetAlert2 sudah dimuat di file `login.html` dan
     `signup.html`, ubah pemanggilan `alert(message)` bawaan menjadi
     `Swal.fire({ icon: 'error', title: 'Gagal', text: message })` atau
     menggunakan SweetAlert Toast agar seragam dengan estetika premium dasbor.

3. Kerentanan Nilai NaN pada Perhitungan Backtesting Model MA
   - Lokasi Masalah:
     js/prediksihasil.js (Garis 550 - 553)
     Membaca input:
     ```javascript
     let cleanProdStr = (inputsProd[i].value || '').replace(/\./g, '').replace(',', '.');
     let cleanProfStr = (inputsProfit[i].value || '').replace(/\./g, '').replace(',', '.');
     fullHistoryButir.push(parseFloat(cleanProdStr));
     fullHistoryProfit.push(parseFloat(cleanProfStr));
     ```
   - Deskripsi Masalah:
     Jika pengguna tidak sengaja mengosongkan salah satu input baris 
     riwayat produksi atau mengetik karakter non-numerik, `parseFloat()` 
     akan mengembalikan nilai `NaN` (Not a Number).
     Nilai `NaN` ini akan didorong ke dalam array `fullHistoryButir` 
     dan dikirim ke `ma-core.js` untuk fungsi `evaluateModelAccuracy`. 
     Di dalam `ma-core.js`, penambahan nilai `NaN` akan merusak seluruh 
     kalkulasi akumulatif, sehingga visual akurasi model di antarmuka 
     akan terus menampilkan teks "NaN%" atau "± NaN Butir".
   - Solusi Perbaikan:
     Beri nilai fallback default `0` atau abaikan baris kosong secara ketat 
     saat parsing input:
     ```javascript
     const prodVal = parseFloat(cleanProdStr);
     const profitVal = parseFloat(cleanProfStr);
     fullHistoryButir.push(isNaN(prodVal) ? 0 : prodVal);
     fullHistoryProfit.push(isNaN(profitVal) ? 0 : profitVal);
     ```

========================================================================
KESIMPULAN AUDIT
========================================================================
Secara umum, arsitektur kode program LIBAS sudah dikembangkan secara rapi 
dan sangat terstruktur. Pemisahan pure function Moving Average di `ma-core.js` 
adalah langkah yang luar biasa untuk menjaga kebersihan kode. 

Namun, perbaikan rute pengalihan logout admin dari `adminlogin.html` ke 
`login.html` wajib segera diselesaikan agar sistem tidak mengalami crash 
404. Begitu pula dengan unifikasi menu sidebar dan penyelarasan fungsi 
`toggleSidebarMenu` demi tercapainya standardisasi DRY yang sempurna.
