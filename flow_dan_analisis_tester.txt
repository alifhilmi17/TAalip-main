1. HASIL ANALISIS ARSITEKTUR KODE & TEKNOLOGI
====================================================================
Berdasarkan analisis menyeluruh terhadap file-file di dalam direktori proyek, aplikasi LIBAS memiliki fondasi arsitektur sebagai berikut:

* Sisi Klien (Frontend): 
  - Menggunakan kombinasi HTML5 semantik, CSS Modern (dengan variabel CSS, efek Glassmorphism premium, animasi Animate.css), dan JavaScript Vanilla (ES6 Modules).
  - Tampilan UI sangat interaktif, elegan, dan memanfaatkan pustaka visual eksternal seperti Chart.js untuk representasi grafik dan SweetAlert2 untuk notifikasi popup yang ramah pengguna.
  
* Sisi Server & Database (Backend):
  - Menggunakan Google Firebase (Firestore Database) untuk penyimpanan data secara real-time dan Firebase Authentication untuk mengelola session login pengguna.
  
* Pembagian Otoritas (Role Management):
  - Sistem memiliki mekanisme deteksi peran (Role) yang membedakan hak akses antara "Admin" (pemilik peternakan/pengelola utama) dan "Petugas" (operator kandang harian).

* Struktur Modul Utama:
  a. Autentikasi: index.html (Gerbang utama) -> login.html & signup.html (Didukung transisi loading "Chicken Running" yang interaktif).
  b. Dashboard Utama (dashboardTAalip.html): Pusat KPI agregat (Populasi, Telur, Keuangan, Mortalitas, Stok Pakan) secara real-time dengan visual grafik tren.
  c. Data Ayam (dataAyamTAalip.html): Log batch populasi, kandang, serta pencatatan ayam afkir.
  d. Kesehatan Ayam (kesehatanayam.html): Log penyakit, jadwal vaksinasi terstruktur, dan rekap mortalitas.
  e. Input Produksi (inputproduksi.html): Input harian hasil telur dengan pembagian telur baik dan telur cacat.
  f. Persediaan Pakan (stokpakan.html & restockreminder.html): Sistem log masuk-keluar pakan dengan notifikasi otomatis saat stok berada di bawah batas aman.
  g. Keuangan (keuangan.html): Buku kas digital peternakan (Pemasukan vs Pengeluaran).
  h. Prediksi Hasil (prediksihasil.html): Sistem pakar mini menggunakan rumus matematika Moving Average (MA) untuk memproyeksikan laba dan hasil panen 7 hari ke depan.
  i. Pusat Dokumen (dokumen.html): Modul ekspor laporan terpadu ke format CSV/Excel.

2. FLOW MENGGUNAKAN APLIKASI (USER FLOW END-TO-END)
====================================================================
Berikut adalah rancangan alur ideal bagi pengguna (baik Admin maupun Petugas) dalam mengoperasikan aplikasi LIBAS secara terstruktur untuk mengelola peternakan sehari-hari:

--- ALUR 1: AKSES & PENGATURAN AWAL (AUTHENTICATION & SETUP FLOW) ---
1. Pendaftaran / Masuk Portal:
   - Pengguna membuka `index.html`, lalu menekan "Masuk ke Portal" (menuju `login.html`) atau "Buat Akun" (`signup.html`) jika belum memiliki kredensial.
   - Pengguna memasukkan username/password. Saat tombol masuk ditekan, animasi transisi ayam berlari akan muncul, disusul pengecekan role oleh sistem di Firestore.
2. Setup Profil & Deteksi Role:
   - Pengguna masuk ke halaman `dashboardTAalip.html`.
   - Jika masuk sebagai Admin, menu "Kembali ke Admin" akan muncul di sidebar. Jika sebagai Petugas, antarmuka dibatasi hanya untuk aktivitas operasional harian.
   - Pengguna dapat menyesuaikan detail informasi diri di halaman `editProfileTAalip.html`.

--- ALUR 2: INISIALISASI POPULASI (CHICKEN INVENTORY SETUP) ---
*Sebelum memulai pencatatan harian, batch ayam harus didaftarkan terlebih dahulu.*
3. Tambah Batch Ayam:
   - Pengguna mengklik menu "Data Ayam" -> klik tombol "Tambah Batch Ayam".
   - Mengisi data: Tanggal Masuk, Jenis Ayam (contoh: Remban / Bujang), Jumlah Populasi Awal, Sisa Ayam, Lokasi Kandang (Kandang A / Kandang B), dan Status (Aktif).
   - Menyimpan data (Data tersimpan di Firestore dan otomatis memperbarui widget total ayam aktif di Dasbor).

--- ALUR 3: RUTINITAS OPERASIONAL HARIAN (DAILY PRODUCTION ROUTINE) ---
*Ini adalah alur kerja yang dilakukan Petugas setiap hari.*
4. Cek Aktivitas & Pengumuman Harian:
   - Di pagi hari, Petugas membuka Dashboard untuk membaca "Pengumuman" dari Admin dan memeriksa checklist "Aktivitas Harian" yang harus diselesaikan.
5. Catat Produksi Telur Harian:
   - Setelah mengumpulkan telur, Petugas mengakses menu "Input Produksi Harian" atau menekan Aksi Cepat "Input Produksi" di Dashboard.
   - Memilih Batch Ayam terkait, memasukkan jumlah Telur Baik (butir) dan Telur Cacat (butir).
   - Klik "Simpan". Grafik tren produksi telur di Dashboard otomatis ter-update secara real-time.
6. Kelola Penggunaan Pakan:
   - Petugas memberi makan ayam, kemudian mengakses menu "Stok Pakan" -> "Catat Log Pakan".
   - Memasukkan data transaksi pakan tipe "Keluar" sebesar berat pakan yang diberikan (Kg).
   - Jika sisa pakan setelah dikurangi berada di bawah batas ambang rendah/kritis, "Alert Banner" merah/kuning akan langsung menyala di bagian atas Dashboard.
7. Catat Kesehatan & Mortalitas (Jika Ada):
   - Jika ditemukan ada ayam yang sakit atau mati, Petugas masuk ke menu "Data Kesehatan Ayam" -> klik "Tambah Log Kesehatan".
   - Mengisi jumlah ayam yang sakit/mati, diagnosis gejala penyakit, dan status penanganan ("Dalam Perawatan" / "Selesai" / "Mati Semua").
   - Data kematian ini akan langsung memotong jumlah "Populasi Ayam Aktif" di widget utama Dashboard dan menampilkan peringatan di Alert Banner.

--- ALUR 4: MANAJEMEN LOGISTIK & KEUANGAN (LOGISTICS & FINANCE FLOW) ---
*Dilakukan saat melakukan pembelian stok atau penjualan hasil panen.*
8. Pembelian Stok Pakan (Restock):
   - Jika menerima notifikasi pakan habis, Admin melakukan pemesanan pakan ke supplier.
   - Setelah pakan datang, masuk ke menu "Stok Pakan" -> "Catat Log Pakan" -> pilih tipe "Masuk" -> masukkan jumlah Kg pakan yang dibeli.
   - Status di "Restock Reminder" diubah menjadi "Selesai".
9. Pembukuan Transaksi Keuangan:
   - Pengguna masuk ke menu "Pemasukan & Pengeluaran" (Keuangan).
   - Catat Pengeluaran: Pembelian pakan, pembelian vaksin, pembayaran listrik, atau gaji pegawai.
   - Catat Pemasukan: Hasil penjualan telur harian kepada pengepul.
   - Grafik perbandingan pemasukan vs pengeluaran mingguan di Dashboard akan langsung menyesuaikan.

--- ALUR 5: PROYEKSI BISNIS & SISTEM PAKAR (PREDICTIVE FORECASTING FLOW) ---
*Dilakukan secara berkala oleh Admin untuk menentukan strategi peternakan ke depan.*
10. Prediksi Hasil & Laba Masa Depan:
    - Admin masuk ke halaman "Prediksi Hasil".
    - Memilih parameter yang ingin dianalisis (contoh: menganalisis berdasarkan 7 hari riwayat terakhir menggunakan Moving Average).
    - Memasukkan harga pakan saat ini per Kg, porsi makan harian ayam, harga telur per papan di pasaran, serta data histori laba nyata.
    - Menekan "Analisis dengan MA".
    - Sistem akan menghitung proyeksi 7 hari ke depan (H+1 sampai H+7) dengan metode Sliding Window, serta menghitung "Rerata Offset" untuk menjaga keakuratan laba bersih riil.
    - Sistem pakar mini akan menerbitkan "Rekomendasi Bisnis" otomatis (Label Hijau = Sangat Sehat, Kuning = Margin Tipis, Merah = Bahaya/Rugi, serta peringatan Hen Day Production di bawah 60% atau tren panen drop drastis).

--- ALUR 6: PELAPORAN & ARSIP (REPORTING & ARCHIVING FLOW) ---
11. Rekap Data & Unduh Laporan:
    - Di akhir bulan, Admin masuk ke "Pusat Dokumen".
    - Memilih jenis data yang ingin diekspor (Data Ayam, Produksi Telur, Keuangan, atau Kesehatan).
    - Mengunduh file laporan dalam format CSV yang kompatibel dengan Microsoft Excel untuk pelaporan fisik atau arsip lokal.

3. PANDANGAN & OPINI TESTER (QA EVALUATION)
====================================================================
Sebagai QA Tester, berikut adalah ulasan objektif mengenai aplikasi LIBAS:

--------------------------------------------------------------------
A. KELEBIHAN APLIKASI (POSITIF & PREMIUM UI/UX)
--------------------------------------------------------------------
1. Estetika Visual Sangat Menawan:
   - Desain layout dashboard sangat premium dengan kombinasi warna ungu, hijau, dan cyan yang serasi, dipadukan dengan efek glassmorphism transparan. Hal ini membuat aplikasi jauh dari kesan "kaku" seperti aplikasi administrasi konvensional.
2. Responsivitas dan Animasi Halus:
   - Penggunaan Animate.css pada komponen stat card memberikan sentuhan interaktif yang memanjakan mata. Keberadaan menu hamburger seluler menjamin kenyamanan akses saat peternak memantau kandang langsung menggunakan smartphone.
3. Fitur Real-Time Sinkronisasi yang Sempurna:
   - Integrasi Firebase Firestore berjalan sangat baik. Saat petugas meng-update data produksi di kandang, layar monitor dasbor milik admin di kantor langsung berubah tanpa perlu me-refresh browser.
4. Nilai Tambah Prediksi yang Cerdas (Sistem Pakar):
   - Logika Moving Average yang mengintegrasikan "Offset Pengeluaran Riil" adalah terobosan fungsional yang sangat cerdas untuk memecahkan bias teori matematika vs kenyataan di lapangan.

--------------------------------------------------------------------
B. ANALISIS POTENSI BUG & CELAH SISTEM (EDGE CASES UNTUK DIWASPADAI)
--------------------------------------------------------------------
Selaku tester, saya mengidentifikasi beberapa kondisi kritis (edge cases) yang berpotensi memicu error atau celah keamanan jika tidak ditangani dengan baik:

1. Validasi Input Pembagian Nol (Division by Zero):
   - Pada rumus Hen Day Production (HDP) di halaman Prediksi dan Dashboard: `(Total Telur / Populasi) * 100%`.
   - Bug Trigger: Jika database populasi ayam bernilai `0` (misal karena belum input batch pertama atau semua ayam sudah diafkir/mati), kode JavaScript berisiko menghasilkan nilai `Infinity` atau `NaN` di layar.
   - Solusi QA: Pastikan ada pengecekan kondisi `if (populasi === 0) return 0;` sebelum melakukan pembagian.

2. Inkonsistensi Format Angka Ribuan (Sanitasi Input):
   - Pengguna di Indonesia seringkali secara tidak sadar mengetik titik atau koma saat menginput nominal uang di keuangan atau prediksi (misal: 25.000 atau 25,000).
   - Bug Trigger: Meskipun sudah ada fungsi pembersih `replace(/\./g, '')`, perlu diuji apakah input non-numerik (huruf/simbol) bisa lolos dan menyebabkan kegagalan kalkulasi database.
   - Solusi QA: Tambahkan attribute `type="number"` atau regex sanitizer yang lebih ketat pada sisi HTML form.

3. Ketergantungan Data Historis pada Halaman Prediksi:
   - Halaman Prediksi membutuhkan data histori produksi H-1 hingga H-7 untuk menghitung Moving Average (MA) periode 7.
   - Bug Trigger: Jika pengguna baru pertama kali memakai aplikasi dan data historis harian di Firestore masih kurang dari 7 baris data, perhitungan MA berisiko memproses nilai `undefined` yang berujung pada grafik kosong atau patah.
   - Solusi QA: Tambahkan fungsi fallback. Jika data aktual kurang dari periode MA yang dipilih, sistem harus menampilkan peringatan yang ramah: "Data historis Anda belum mencukupi (Minimal 7 hari). Silakan isi data simulasi terlebih dahulu."

4. Keamanan Sisi Klien (Frontend Role Guard):
   - Pembatasan menu Admin vs Petugas saat ini diatur menggunakan CSS/JS di frontend (menyembunyikan container switch admin).
   - Bug Trigger: Pengguna yang cerdas secara teknis dapat memanipulasi inspect element (F12) untuk menampilkan tombol admin secara paksa dan mencoba mengakses halaman admin di subfolder `admin.frontend/`.
   - Solusi QA: Pastikan Firestore Security Rules dikonfigurasi dengan ketat, sehingga dokumen di collection `admin` benar-benar terkunci secara backend dan hanya bisa dibaca oleh UID yang valid.

--------------------------------------------------------------------
C. REKOMENDASI PENINGKATAN FITUR (FOR TA/DEVELOPER)
--------------------------------------------------------------------
Untuk membuat aplikasi ini semakin sempurna dan bernilai tinggi dalam sidang Tugas Akhir (TA), berikut beberapa saran pengembangan:

1. Pemasangan Input Masking:
   - Pasang library seperti `cleave.js` atau manipulasi regex pada input keuangan agar saat pengguna mengetik angka `250000`, di layar otomatis terformat secara visual menjadi `Rp 250.000` secara real-time. Ini akan meningkatkan aspek ergonomi aplikasi.
2. Fitur Offline Mode (PWA):
   - Peternakan sering kali terletak di daerah rural/pedesaan dengan koneksi internet yang tidak stabil.
   - Saran: Mengonversi sistem ini menjadi Progressive Web App (PWA) dan mengaktifkan Firestore Offline Persistence. Data yang diinput saat offline akan disimpan di memori lokal browser, lalu otomatis disinkronkan ke cloud saat internet terhubung kembali.
3. Cetak PDF Resmi:
   - Selain format CSV, tambahkan opsi cetak laporan langsung ke format PDF dengan kop surat peternakan resmi di halaman "Pusat Dokumen" agar laporan siap dicetak fisik untuk rapat bisnis.
